# 한국전력공사 정보공개 청구 지원 시스템

정보공개 청구인이 제출한 내용을 접수 → AI가 요청대상 식별 및 반복 청구 자동 판정 →
배정담당자가 업무담당자에게 배정 → 업무담당자가 법령 조문 근거의 판단 위저드로
공개 여부를 확정하는 흐름을 지원하는 로컬 웹 대시보드입니다.

SCADA 프로젝트(`../scada_system_agent`)와 동일한 스택(FastAPI + Jinja2 + SQLite + 바닐라 JS)과
디자인 시스템을 재사용해 만들었고, `docs/blueprint.jpeg`(정보공개 청구 처리 흐름도)의 판단
절차를 그대로 코드로 옮겼습니다.

더 자세한 배포/개발 표준/점검 문서는 `docs/README.md`에 안내가 있습니다.

## 실행 (가장 쉬운 방법)

`실행.bat`을 더블클릭하세요.

- **처음 실행**: 필요한 패키지를 자동 설치(1~2분) → 서버 시작 → 브라우저 자동 오픈
- **다음부터**: 설치 단계 없이 몇 초 안에 바로 시작
- 뜨는 검은 콘솔 창이 서버입니다 — 끄지 말고 그대로 두고, 종료하려면 창을 닫으면 됩니다
- Python이 PATH에 없으면 오류 메시지를 띄우고 멈춥니다. 그 경우 Python을 설치한 뒤 다시
  실행하세요.

### 개발용 실행
```bash
cd info_disclosure_request
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

### 테스트 실행
```bash
pip install -r requirements-dev.txt
pytest
```
`tests/`에 FastAPI `TestClient` 기반 자동화 테스트가 있습니다(인증/계정 잠금, 역할별 접근
통제, 배정·거절·재배정·판단 흐름, 계정 관리). 테스트는 임시 SQLite DB를 새로 만들어 쓰므로
실제 `data/info_disclosure.db`에는 영향이 없습니다.

## 계정과 화면

로그인 계정에 따라 접속 즉시 다른 화면으로 이동하며, 다른 역할의 URL로 직접 들어가려 해도
서버가 자기 화면으로 되돌려보냅니다(API는 403). 서버를 처음 켰을 때 없는 계정은 아래
기준으로 자동 생성됩니다(`app/deps.py`의 `DEFAULT_ACCOUNTS`, 계정별로 없을 때만 생성 —
이미 있는 계정의 비밀번호는 건드리지 않음).

| 역할 | 기본 계정 | 로그인 후 첫 화면 | 할 수 있는 일 | 소속 |
|---|---|---|---|---|
| 시스템관리자 | `admin` / `admin` | 계정 관리 (`/admin/users`) | 계정 추가·수정·삭제 | 한국전력공사 |
| 총괄관리자 | `manager` / `manager` | 대시보드 (`/`) | 전체 청구 조회·판단·설정 변경, 담당자 직접 재배정 | 한국전력공사 |
| 배정담당자 | `dispatcher` / `dispatcher` | 배정 대기 (`/dispatch`) | 업무담당자 배정(직접 재배정 포함), 청구인 이력 조회 (판단·수동 접수는 불가) | 외부업체 가능 |
| 업무담당자 | `staff1`~`staff10` (각각 동일 비밀번호) | 내 업무 (`/requests`) | 본인에게 배정된 청구만 위저드로 판단, 잘못 배정된 건은 거절(재배정 요청), 처리기한 연장 | 한국전력공사 |

시스템관리자는 `/admin/users`에서 계정을 추가·수정·삭제할 수 있습니다(아이디는 배정·처리
이력이 문자열로 참조하고 있어 수정 시에도 변경 불가, 역할/소속/비밀번호만 수정 가능. 마지막
남은 시스템관리자 계정의 역할 변경과 자기 자신 삭제는 불가). 기본 계정들은 모두 예시용
비밀번호이므로, 실제 배포 전에는 반드시 변경하세요. 로그인은 계정당 5회 연속 실패 시
5분간 잠깁니다(메모리 기반, 서버 재시작 시 초기화).

## 배정 대기 화면의 "AI 판단하기" (데모용)

`/dispatch`에서 각 미배정 청구는 원문 전체가 바로 보이고, 옆에 "🤖 AI 판단하기" 버튼이
있습니다. **실시간 AI 계산이나 무작위 추천은 전혀 하지 않습니다** — 클릭하면 그 청구의
접수 파일명과 동일한 이름의 예시 결과 파일을 `data/ai_recommendations/`에서 찾아 그대로
보여줄 뿐입니다.

- 예시 결과 파일이 있으면 → 추천 담당자 1·2·3순위가 표시되고, 클릭하면 그 담당자에게 바로 배정
- 없으면 → 아직 예시가 준비되지 않았다는 안내와 "AI로 생성하기" 버튼이 뜨는데, 이 버튼도
  실제로 뭔가를 생성하지 않고 "이 데모는 사전 준비된 5건만 지원합니다"라는 안내만 보여줍니다

`data/watch/`에 넣어둔 예시 청구 10건 중 5건(`202602 01~05`)에는
`data/ai_recommendations/`에 짝이 되는 결과 파일이 미리 준비되어 있고, 나머지 5건
(`202602 06~10`)은 일부러 비워뒀습니다. 결과 파일 형식:
```
1순위: staff2
2순위: staff5
3순위: staff8
사유: (표시될 설명 문구, 선택)
```
새 예시를 추가하려면 `data/watch/{파일명}.txt`와 같은 이름으로
`data/ai_recommendations/{파일명}.txt`를 만들면 됩니다.

## 처리 흐름

```
청구인(txt) → 감시 폴더 자동 수집 → AI 자동식별(요청대상 추출 + 반복 청구 자동 판정)
   → 반복 청구면 즉시 "종결"로 자동 확정
   → 아니면 배정담당자가 업무담당자에게 배정
      → 업무담당자가 위저드로 판단(정보해당 → 진정질의/정보부존재 → 대체정보 → 비공개대상 → 부분공개)
      → 최종 통지(공개/부분공개/비공개/정보부존재/진정질의) 확정
→ 총괄관리자는 전 과정을 대시보드에서 조회·개입 가능
```

청구 접수는 감시 폴더 자동 수집만 지원합니다 — 화면에서 직접 입력하는 수동 접수 기능은
없습니다(의도적으로 제거됨, 아래 "청구 자동 접수" 참고).

## 배정 중 재배정 · 처리기한 · 통지서

- **업무담당자의 거절(재배정 요청)**: 잘못 배정된 청구는 업무담당자가 직접 담당자 없이
  반려할 수는 없고, 넘길 담당자를 1~3명 지명해야 합니다. 지명된 후보는 배정 대기 화면에
  "🔁 이전 담당자가 재배정을 요청했습니다"로 표시되고, 배정담당자/총괄관리자가 그중 한
  명을 클릭해 확정합니다. 이미 진행된 판단 내용은 다음 담당자가 그대로 이어받습니다.
- **총괄관리자/배정담당자의 직접 재배정**: 이미 배정된(미확정) 건도 담당자 동의 없이
  `/requests/{id}`에서 바로 다른 담당자로 재배정할 수 있습니다.
- **처리기한(D-day)**: 정보공개법 제11조 기준 접수일+10일을 목록·배정 대기·상세·대시보드에
  표시합니다. 배정된 업무담당자 본인 또는 총괄관리자가 1회에 한해 +10일 연장 가능
  (제11조 제2항, 역일 기준 계산 — 아래 "알려진 제약사항" 참고).
- **통지서 인쇄**: 판단이 완료된 건은 `/requests/{id}/notice`에서 인쇄/PDF 저장용 문서
  화면을 열 수 있습니다(별도 문서 생성 라이브러리 없이 브라우저 인쇄 기능만 사용).
- **새 배정 알림**: 업무담당자의 "내 업무" 화면은 20초 간격으로 폴링해 새로 배정된 청구가
  있으면 토스트로 알려줍니다(실시간 SSE/웹소켓이 아니라 대시보드와 동일한 폴링 방식).

## 청구 자동 접수 (감시 폴더, 유일한 접수 경로)

`data/watch/` 폴더에 `숫자6~8자리_이름.txt` 형식 파일을 넣으면 서버가 주기적으로(기본 60초)
자동 스캔해 접수합니다. 화면에서 직접 입력하는 수동 접수 경로는 없으므로, 전화·방문 등
비전자 경로로 들어온 청구도 이 폴더에 `.txt` 파일로 넣어야 시스템에 반영됩니다. 파일 내용
형식:
```
청구인: 홍길동
연락처: 010-1234-5678
---
(청구 내용 본문)
```
헤더 없이 본문만 넣으면 청구인 이름이 "미상"으로 접수됩니다. `data/watch/`에는 배정 대기
큐를 바로 확인해볼 수 있는 예시 청구 10건이 들어있습니다(그 중 5건은 "AI 판단하기" 예시
결과도 함께 준비되어 있습니다 — 위 "배정 대기 화면의 AI 판단하기" 참고).

## AI 역할

내장 로컬 API(`app/ai_runtime/api.py`, 127.0.0.1:8011)가 청구 접수 시 자동으로:
1. 청구 원문에서 **요청대상** 문장을 추출하고 요약
2. 과거 접수 이력과 문자열 유사도를 비교해 **반복 청구 여부를 자동 판정**(임계값 이상이면 즉시 종결)
3. 진정·질의 가능성, 비공개 사유 키워드 매칭 여부를 **참고용 힌트**로 제시

규칙/키워드 기반의 가벼운 구현이며, 정보 해당 여부·진정질의·정보부존재·비공개 대상·부분공개
가능 여부 등 **실제 법적 판단은 전부 업무담당자가 위저드에서 직접 확정**합니다. (동작 원리
상세는 `app/ai_runtime/utils_text.py` 참고)

## 환경변수
- `FOIA_WATCH_DIR`: 청구서 자동 수집 디렉토리 (기본 `data/watch`)
- `FOIA_AI_SERVER_HOST` / `FOIA_AI_SERVER_PORT`: 내장 AI 식별 API 주소(기본 127.0.0.1:8011)
- `FOIA_SCAN_INTERVAL`: 감시 폴더 자동 스캔 간격(초), 기본 60
- `FOIA_DB_PATH`: SQLite 파일 경로 (기본 `data/info_disclosure.db`)
- `FOIA_NO_BROWSER`: `1`이면 실행 시 브라우저 자동 오픈 비활성화
- `FOIA_AUTH_COOKIE_SECURE`: `1`이면 세션 쿠키에 `Secure` 플래그 적용(HTTPS 배포 시)
- `FOIA_AUTH_SECRET`: 세션 서명키를 직접 지정(미설정 시 최초 실행 때 자동 생성해 DB에 저장).
  여러 사용자가 접속하는 서버로 배포할 때의 리버스 프록시·TLS·DB 보호 방법은
  `docs/DEPLOYMENT.md` 참고

## 알려진 제약사항
- 실제 PDF/HWPX 원문 파싱은 포함하지 않았습니다. 텍스트 붙여넣기 또는 `.txt` 자동 수집만
  지원하며, PDF/HWP → txt 변환은 이 시스템 바깥의 별도 단계로 가정합니다. 향후
  `pdfplumber`, `olefile` 등을 추가해 원문 파싱 단계를 확장할 수 있습니다.
- 반복 청구 자동 판정은 문자열 유사도 기반이라, 표현만 다르고 내용이 같은 청구는 놓칠 수
  있습니다. 자동 판정 결과는 청구 상세 화면에서 항상 확인 가능합니다.
- 이 판단 흐름은 원본 도표(`docs/blueprint.jpeg`) 표기를 그대로 코드화한 것이며 법률
  자문이 아닙니다. 실제 운영 적용 전 관계 법령과 원본 문서로 재확인하시기 바랍니다.
- 계정 4개의 기본 비밀번호는 아이디와 동일한 테스트용 값입니다. 실제 배포 전 변경하세요.
- 처리기한(D-day)은 정보공개법 제11조 기준 접수일+10일(1회 연장 시 +10일)을 **역일(달력일)**
  기준으로 계산합니다. 실제로는 공휴일 등을 제외한 근무일 기준일 수 있어 참고용입니다.
- 상태 변경 POST에는 CSRF 토큰 검증이 적용돼 있습니다(로그인 시도 제한도 구현됨 — 위
  "계정과 화면" 참고, 자동화 테스트는 위 "테스트 실행" 참고). 2026-09-07 점검 결과와

## SCADA 프로젝트와의 관계
초기 디자인과 코드 구조, 인증 방식(pbkdf2 + HMAC 세션 쿠키)을 `scada_system_agent`
프로젝트에서 재사용했습니다. 현재 웹 화면의 색상·서체는 KRDS 기준으로 변경했습니다. 기능적으로는 서로 무관한 별개
프로젝트입니다. `docs/reference/scada_aiops_blueprint.html`은 SCADA 프로젝트의 기술 청사진을
UX 참고용으로 복사해 둔 것으로, 이 프로젝트 자체의 문서가 아닙니다.
