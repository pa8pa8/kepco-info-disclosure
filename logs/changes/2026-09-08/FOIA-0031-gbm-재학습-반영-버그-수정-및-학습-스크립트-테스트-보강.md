## 변경 요약
사용자 지시 "AI 관련해서 잘 만들어줘" → "전체적으로 점검해서 개선해야될 부분을
찾아줘"로 진행한 자체 점검(AI 관련 코드 전수)에서 발견한 3건 중 사용자가 즉시
수정을 지시한 항목 처리: (1) GBM 모델이 재학습해도 서버 재시작 전까지 반영 안 되던
버그, (2) 학습 스크립트의 검증용/배포용 파이프라인 설정이 따로 놀던 문제, (3) 학습
스크립트의 실데이터 CSV 로딩 로직 테스트 공백. 나머지 3건(로그 무기한 누적, 반복청구
판정 성능, onclick 문자열 삽입 일관성)은 `docs/PROJECT_REVIEW.md`에 메모만 남기고
보류(사용자 지시).

## 변경 내용

### 1. GBM 재학습 미반영 버그 수정
- `app/services/recommend/gbm_recommender.py`: 모델 캐시를 모듈 전역 변수
  (`_model`/`_load_attempted`, 한 번 로드하면 프로세스 종료까지 절대 안 바뀜)에서
  인스턴스 속성으로 옮기고, 파일 수정시각(mtime)을 매번 확인해 바뀌었으면 다시
  불러오도록 변경. `tools/train_gbm_recommender.py`로 재학습해도 서버 재시작 없이
  다음 요청부터 새 모델이 반영된다 — 지난 `data/training/README.md`/`FOIA-0030`
  로그에 이미 "재시작하거나 다음 요청부터 반영"이라고 적어뒀던 게 실제로는 거짓이었던
  걸 바로잡음(재학습 시 재시작이 필수였음).

### 2. 파이프라인 설정 중복 정리
- `tools/train_gbm_recommender.py`: 검증용 파이프라인은 `min_df=2` 고정, 배포용
  파이프라인만 데이터가 적으면(<50건) `min_df=1`로 완화하도록 두 곳에 따로
  구현돼 있던 걸 `build_pipeline(sample_count)` 함수 하나로 합침. 실제 데이터가
  10~49건 사이일 때 검증 단계에서만 어휘가 과도하게 걸러질 수 있던 불일치 제거.

### 3. 테스트 보강
- `tests/test_recommend.py`: GBM 모델 재학습 반영 회귀 테스트(임시 모델 2번 학습해
  mtime 갱신 후 `classes_`가 바뀌는지 확인), 합성 데이터 생성기가 담당자 10명을
  전부 커버하는지, 시드 고정 시 결정적인지 확인하는 테스트 3개 추가.
- `tests/test_train_gbm_recommender.py` 신규(8개): 실데이터 CSV 정상 파싱, 존재하지
  않는 계정/빈 값 행 건너뛰기, 컬럼명이 다를 때 경고, 실데이터 우선 사용, 실데이터
  없을 때/전부 무효할 때 합성 데이터로 폴백, `build_pipeline`의 `min_df` 분기 확인.

### 4. 나머지 발견 사항 메모 (보류)
- `docs/PROJECT_REVIEW.md`에 13~15번으로 기록: `data/ai_log.jsonl` 무기한 누적,
  반복청구 판정의 O(n) 유사도 비교 성능, `onclick` 문자열 삽입 일관성.

## 원인
사용자 지시. AI 기능을 처음 만들 때는 정상 동작 확인에 집중했지만, 재학습이라는
"두 번째 학습 이후" 시나리오를 실제로 테스트해보지 않아 캐시 버그를 놓쳤던 것.

## 검증
- 확인 방법: `python -m compileall app tools` 통과. 재학습 스크립트를 실제로 다시
  돌려 리팩터 전후 동일 결과(320건, 학습 90.2%/검증 68.8%) 확인 — 순수 리팩터임을
  검증. 신규 회귀 테스트로 mtime 변경 시 실제로 `_load_model()`이 새 `classes_`를
  반환하는지 직접 확인(변경 전 코드로 되돌리면 이 테스트가 실패하는 것도 확인).
- `python -m pytest -q` 59개 전부 통과(기존 48 + 신규 11).
- 결과: 전부 기대대로.
