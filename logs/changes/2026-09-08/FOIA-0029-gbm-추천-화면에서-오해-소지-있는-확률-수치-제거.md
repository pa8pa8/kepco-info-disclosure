## 변경 요약
FOIA-0028 직후 사용자 질문: "난 답을 준적이 없는데 어떻게 정확도가 68.8%가 나오니" —
GBM 학습 스크립트가 출력한 "검증 정확도 68.8%"가 실제 배정 정확도로 오해될 수 있다는
정확한 지적. 확인해보니 그 숫자는 내가(Claude가) 직접 만든 합성 데이터의 규칙을
모델이 얼마나 잘 재현하는지를 잰 것일 뿐, 실제 정답과는 무관했다. 화면(웹 UI)에 이미
노출돼 있던 같은 성격의 수치(추천 담당자별 확률 %)를 제거해달라는 후속 지시에 따라
수정.

## 변경 내용
- `app/services/recommend/gbm_recommender.py`: `reason` 문자열에서
  "staff10 23% · staff8 20% · staff5 16%" 같은 클래스별 확률 수치를 제거. 1·2·3순위
  랭킹(어차피 상대적 순서라 참고할 여지가 있음)은 그대로 유지하고, 문구를
  "GradientBoost 추천 순위입니다. ⚠ 실제 배정 이력이 아직 부족해 합성 데이터로 학습된
  모델이라 정확도가 검증되지 않았습니다 — 참고용으로만 활용하세요."로 교체 — 왜
  이 숫자를 뺐는지 코드 주석으로도 남김.
- `tools/train_gbm_recommender.py`의 콘솔 출력("학습 정확도 90.2% / 검증 정확도
  68.8%")은 그대로 둠 — 이건 화면(사용자가 보는 웹 UI)이 아니라 스크립트를 직접
  실행하는 개발자용 진단 출력이라, 애초에 "무엇을 재현하는 정확도인지" 맥락(스크립트
  옆의 학습 데이터가 합성 데이터라는 걸 실행한 사람이 알고 있음)이 있는 자리라
  판단이 다름.

## 원인
사용자 직접 지적 + 후속 지시("화면에서 빼봐"). 합성 데이터로 낸 확률/정확도 수치를
실제 업무 화면에 그대로 노출하면, 실사용자가 "68.8%" 혹은 "23%" 같은 숫자를 실제
정확도로 오인할 위험이 크다고 판단.

## 검증

  없어 문구 교체와 무관하게 통과).

  텍스트를 직접 추출해 확인 — 퍼센트 기호(`%`)가 전혀 없고 새 경고 문구만 표시됨.
- 결과: 기대대로.
