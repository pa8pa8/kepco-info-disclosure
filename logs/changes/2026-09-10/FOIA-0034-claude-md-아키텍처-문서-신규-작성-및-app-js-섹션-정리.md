## 변경 요약
코드베이스에 처음 들어오는 AI 도구(ChatGPT/Gemini 포함)나 개발자가 빠르게 구조를
파악할 수 있도록 루트에 `CLAUDE.md`를 신규 작성했다. 기존 코드 자체의 일관성/모듈화는
점검 결과 이미 양호했음을 확인했고(주요 파일 직접 검토, 인용부호 스타일 통계 확인),
유일하게 섹션 구분이 부족했던 `app/static/js/app.js`에 Python 쪽과 동일한 스타일의
구획 주석을 추가했다.

## 변경 내용
- `CLAUDE.md` 신규: 실행/테스트 명령, 모듈이 왜 이렇게 나뉘었는지(과거 main.py 1000줄
  분리 이력), 요청-판단 흐름(`foia_core.py`), 추천 엔진 플러그인 구조(`ENGINES`
  레지스트리 + `base.py` 공유 로직), 로컬 AI 사이드카(`ai_runtime/`) 구조, 인증/CSRF
  모델, 테스트 fixture 구조, 학습 데이터 파이프라인을 정리.
- `docs/README.md`: 문서 색인 표에 `CLAUDE.md` 행 추가.
- `app/static/js/app.js`: 로직 변경 없이 `// ── 섹션 ──` 구획 주석을 전체에 추가(기존엔
  2곳뿐이었음). `escapeHtml` 함수를 유틸리티 섹션으로 위치만 이동(JS 함수 선언 호이스팅
  덕분에 동작 영향 없음 — `node --check` 문법 확인 + diff로 로직 미변경 확인).

## 원인
- 사용자 요청: "코드 전체 통일성을 줘 / 모듈화를 잘 해줘 / ChatGPT, 제미나이, 개발자가
  이어서 코딩하기 좋도록 문서화해줘."
- `app/db.py`(501줄), `app/routers/requests.py`(385줄) 등 큰 파일을 직접 읽어 검토한
  결과 이미 섹션 주석·일관된 에러 응답 형식·docstring 스타일을 따르고 있어 "스파게티"로
  볼 근거가 없었음 — 실제로 손댈 곳은 `app.js`의 섹션 구분 부재와, 코드 자체보다는
  "처음 보는 사람을 위한 지도" 문서의 부재였다.
