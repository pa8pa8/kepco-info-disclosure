## 변경 요약
KRDS 라이트 테마 전역 적용 및 배정 대기 화면 재구성

## 변경 내용
- `app/static/css/style.css`: 전역 색상 토큰(`:root`)을 기존 다크 네이비 테마에서 KRDS 스타일의
  밝은 배경 + 흰 카드 테마로 교체. 사이드바는 기존 다크 남색을 유지하되 `--sidebar-*` 전용
  변수로 분리(본문 텍스트/배경 토큰과 혼용되지 않도록). 배지·상태알약(status-pill)·요약카드·토스트·
  검색결과·판단 위저드 카드 등 다크 배경을 전제로 하드코딩되어 있던 rgba 값들을 밝은 배경에서
  대비가 나오도록 전부 재조정.
- `app/static/css/style.css`: 배정 대기 화면 전용 클래스 추가(`.dispatch-item`,
  `.dispatch-card-head`, `.dispatch-target`, `.dispatch-label`, `.link-more`,
  `.assign-panel-title/-hint`, `.rank-primary`, `.rank-secondary(-row)`, `.assign-reason`).
- `app/templates/dispatch.html`: 청구 카드를 좌(청구 원문)/우(업무담당자 배정) 2단 레이아웃으로
  재구성하고 "미배정" 배지, "청구 상세 보기" 링크, 1·2·3순위 추천 버튼 UI를 추가.
  최근 배정 이력 표의 상태알약을 "완료"(normal)/"판단중"(info)으로 톤·라벨 정리.
- `app/static/js/app.js`: `renderRecommendations()`를 새 `.rank-primary`/`.rank-secondary-row`
  마크업에 맞게 재작성(클릭 시 "AI 판단하기" API 응답을 받아 동적으로 렌더링하는 경로도
  Jinja 템플릿과 동일한 시각 결과가 나오도록 일치시킴).

## 원인
팀장 지시: Figma에서 KRDS(범정부 UX디자인시스템) 컴포넌트를 참고해 만든 디자인 뼈대
(`docs/design/krds-dispatch-draft.svg`, FOIA-0002)를 실제 화면 코드에 반영. 색상·레이아웃
토큰이 `style.css`의 `:root`와 `base.html`에 전역으로 걸려 있어 배정 대기 화면만 부분
적용하면 다른 화면과 스타일이 어긋나므로, 전역 토큰을 먼저 교체하는 방식으로 진행(사용자 승인).

## 검증
- 확인 방법: `uvicorn app.main:app`으로 로컬 기동 후 Playwright로 로그인 플로우(관리자/배정담당자)를
  거쳐 `/login`, `/`(대시보드), `/requests`, `/requests/{id}`, `/settings`, `/dispatch`
  전체 화면을 스크린샷으로 캡처해 육안 검증. `data/watch/`의 예시 청구 10건이 배정 대기 화면에
  좌/우 2단 카드로 정상 렌더링되고, 5건은 사전 준비된 AI 추천 1·2·3순위가 표시됨을 확인.
- 결과: 전 화면에서 다크→라이트 전환 후 텍스트 대비 문제나 깨진 레이아웃 없음. 기능(로그인,
  역할별 리다이렉트, 배정, AI 추천 표시)은 색상 변경 전과 동일하게 동작.

## 리스크
- 영향 범위: 전역 CSS 변수를 바꿨기 때문에 이 커밋 이후 추가되는 모든 화면/컴포넌트는 라이트
  테마 색상 토큰을 기준으로 작성해야 함(다크 배경 전제의 `rgba(255,255,255,.05)` 류 스타일을
  그대로 복사하면 흰 배경에서 거의 안 보이는 요소가 생김).
- 주의사항: `/requests` 목록 표의 "요청대상/배정/상태/통지 유형" 헤더가 좁은 컬럼 폭 때문에
  줄바꿈되어 보이는 기존 레이아웃 이슈를 확인했으나, 이번 작업 범위(전역 테마 + 배정 대기 화면)
  밖이라 별도로 손대지 않음.

## 다음 조치
- 후속 작업: `/requests`, `/requests/{id}` 등 나머지 화면도 순차적으로 KRDS 컴포넌트 톤에 맞춰
  마크업을 다듬을지 여부 확인 필요. `/requests` 목록 표 컬럼 폭 이슈는 별도 티켓으로 분리 검토.
  실제 Figma KRDS 공식 컴포넌트 라이브러리 인스턴스 적용 여부는 미확정(현재는 색상 토큰 수준의
  근사치 반영).
