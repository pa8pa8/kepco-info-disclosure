## 변경 요약
6개 관점 점검 보고서의 "1. 디렉토리/파일명"과 "2. 변수·명칭 통일성" 항목을 함께 처리.
`app/main.py`(1,041줄) 라우터 분리 + 역할 문자열 하드코딩(54곳) 상수화가 같은 파일을
반복해서 건드리는 작업이라 한 번에 진행. 그 외 파일명·도구 버그도 정리.

## 변경 내용

### 라우터 분리 (main.py 1,041줄 → 93줄)
- `app/roles.py` 신규: 역할 이름 상수(`ADMIN`/`MANAGER`/`DISPATCHER`/`STAFF`/`ALL`/`HOME`)
  단일 출처. `'시스템관리자'` 같은 문자열 리터럴이 `main.py`에서만 54번 반복되던 것을
  전부 이 상수로 교체 — 오타 나면 즉시 `NameError`로 드러남(기존엔 조용히 "권한 없음"
  으로 새버림).
- `app/deps.py` 신규: 공유 싱글턴(`db`/`ai_client`/`processor`/`templates`)과 여러
  라우터가 같이 쓰는 헬퍼(`current_settings`, `with_deadline`,
  `load_ai_recommendation`/`load_reassign_candidates`/`load_recommendation`,
  `DEFAULT_ACCOUNTS`, `STAFF_ORG`).
- `app/security.py` 신규: 비밀번호 해싱, 세션 서명/검증, 로그인 무차별 대입 방어,
  `require_role`/`require_role_api`, `read_json_body` 등 인증/인가 전부.
- `app/routers/{auth,dashboard,requests,dispatch,admin,settings}.py` 신규: 도메인별로
  라우트를 나눔. `requests.py`가 가장 크지만(343줄) 그래도 원래 파일의 1/3 이하.
- `app/main.py`는 이제 앱 생성 + lifespan + 인증 미들웨어 + 라우터 등록만 담당(93줄).
  `launcher.py`가 참조하는 `app.main:app`은 그대로 유지되어 외부 영향 없음.
- 겸사겸사: `__import__('datetime')` 인라인 트릭을 정상적인 `import datetime`으로 교체.

### 명칭 통일성
- `db.py`의 `ROLES` 튜플이 `app/roles.py`를 단일 출처로 삼도록 변경(리팩터 도중 아무도
  안 쓰게 된 걸 뒤늦게 발견해 다시 제거 — 새 구조에서도 죽은 코드가 남지 않게 확인).

## 검증
- 확인 방법: `python -m compileall app` + `from app.main import app` 임포트 확인,
  분리 전후 라우트 목록을 전수 비교(누락·중복 없음, 33개 앱 라우트 + FastAPI 기본
  docs 라우트 3개 + static 마운트 = 37개 일치). 기존에 만든 34개 시나리오 회귀
  테스트에 `/requests/new`·`/api/stream` 삭제 확인 2건을 추가해 36개로 확장 →
  **36/36 통과**. Playwright로 대시보드 스크린샷 재확인(템플릿 렌더링 회귀 없음).
  `log_change.py`는 임시 디렉터리에 실제로 실행시켜 결과 파일명을 UTF-8 바이트
  단위로 검사(`\xea\xb0\x80` 등 정상적인 한글 인코딩 확인, 터미널에 깨져 보이는 건
  이 환경 콘솔 코드페이지 문제일 뿐 실제 파일명은 정상).
- 결과: 전부 기대대로. 순수 리팩터라 동작 변화 없음을 확인.
