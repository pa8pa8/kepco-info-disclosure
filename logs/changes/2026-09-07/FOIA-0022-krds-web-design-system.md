## 변경 요약
실제 웹 시스템에 KRDS 기반 공통 디자인과 로컬 Pretendard GOV 서체 적용

## 변경 내용
- `app/static/css/krds.css`: 공식 KRDS primary/gray/상태 색상, 로컬 웹폰트,
  17px 본문·150% 줄 간격, 버튼 계층·입력창·표·배지·카드·로그인 화면 스타일.
  기존 `style.css`를 유지하고 후속 스타일시트로 적용한다.
- 공통 base/login/setup 템플릿: KRDS CSS 연결, 화면별 제목, 본문 바로가기,
  현재 메뉴의 aria-current, 기관명 표시. 1024px 이하에서도 역할별 메뉴를 표시한다.
- 배정/청구 목록·상세/청구인 이력/계정 목록·수정 템플릿 및 `app.js`:
  인라인 시각 스타일을 공통 클래스로 정리하고 입력 필드에 접근성 이름 추가.
  담당자 검색 결과를 버튼으로 전환, 재배정 후보의 aria-pressed·선택 후 포커스 복원 적용.
  기존 폼 이름·ID·API·권한 조건·선택 제한을 유지한다.
- 통지서 미리보기: KRDS CSS를 `media="screen"`으로 연결. 인쇄 레이아웃 유지.
- `app/static/fonts/pretendard-gov/`: 공식 Regular/Bold WOFF2 원본과 OFL 라이선스,
  고정 커밋·SHA-256·출처 기록을 포함. 서버 실행 시 외부 CDN 의존성 없음.
- README·docs 안내·design README에 적용 범위·공식 출처·검증 결과 기록.
  합성 데이터로 실제 화면 캡처 5개와 `krds-web-verification.json` 저장.
- 최초 Figma 요청은 대상 빈 페이지 및 KRDS 버튼 조회까지 확인했으나, 이후 자산 조회가
  자동 승인 검토의 Codex 사용량 한도 오류로 차단됨. Figma 캔버스 작성은 수행하지 못함.
  사용자 후속 요청 "디자인을 KRDS 디자인으로 변경해줘"에 대해 적용 대상을 질문하고,
  실제 웹 시스템을 대상으로 진행한다는 가정을 안내한 후 웹 디자인을 구현함.

  위한 사용자 요청. 작은 화면에서 메뉴가 숨겨지고 배정 카드가 2열로 유지되던 문제를 함께 수정.

## 검증
- `python -B -m pytest -q -p no:cacheprovider`: **34 passed in 9.21s**.
  기존 fixture의 임시 DB·감시 폴더·추천 폴더 격리를 사용함.
- `node --check app/static/js/app.js` 및 수정 템플릿 Jinja 파싱 통과.
- 임시 Playwright 검증 스크립트의 FastAPI TestClient 요청 연결 방식으로 Chromium 검증.
  앱 서버 포트·로컬 AI 서버를 띄우지 않고 임시 DB의 합성 청구 3건만 사용.
- 화면 21개 조합(1440/1024/768/390px 포함): 문서 가로 넘침 없음, 폰트 로드 성공,
  브라우저 JS 오류 0, 정적 파일 오류 0. PC·모바일 배정 화면과 대시보드 캡처 육안 검토.
- 담당자 검색 결과 Enter 배정 후 임시 DB의 assigned_to 일치, 재배정 후보 Space/Enter
  선택·해제, 4번째 후보 차단, 선택 후 포커스 유지 확인.
- 요약 카드 6종 텍스트 명도 대비 5.26:1~7.95:1, 비활성 입력창 색상 적용 확인.
- 인쇄 모드에서 도구 모음 숨김·문서 테두리 제거 확인.
- 검증 전후 프로젝트 `data/` 전체 파일 SHA-256 일치. 실제 업무 데이터 변경 없음.

## 리스크
- 영향 범위: 웹 프런트엔드 전반. 백엔드 판단·권한·접수·DB 스키마는 변경하지 않음.
- 기존 CSS 뒤에 KRDS 보정 CSS를 읽는 구조이므로 신규 UI는 `krds.css`와 공통 클래스를
  우선 사용하고, 인라인 색상·글자 크기 추가를 피해야 한다.
- 정적 폰트 2개로 배포 크기가 약 4.2MB 증가. 원본 OFL 라이선스를 함께 배포해야 한다.
- 공식 Component Kit 전체 이식이나 KRDS 준수 인증은 아니다. Chromium 이외 브라우저와
  보조기기의 전체 접근성 검증은 포함하지 않음.
