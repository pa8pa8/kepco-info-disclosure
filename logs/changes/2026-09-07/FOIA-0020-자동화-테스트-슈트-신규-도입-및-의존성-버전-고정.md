## 변경 내용

### 자동화 테스트 슈트 신규 도입 (`tests/`, 34개)
- `tests/conftest.py`: `app.config`가 import 시점에 환경변수를 읽는 구조를 이용해, 앱을
  import하기 전에 `FOIA_DB_PATH`/`FOIA_WATCH_DIR` 등을 임시 디렉터리로 돌려 실제
  `data/info_disclosure.db`에 영향 없이 격리 실행되게 함. 세션당 한 번 lifespan을 태워
  기본 계정을 시딩하고, 매 테스트마다 새 쿠키 저장소(TestClient)를 발급해 로그인 세션이
  테스트 간에 새는 것을 방지. 청구/판단 테이블은 매 테스트 전후로 비움(계정 테이블은
  세션 내내 유지).
- `app/main.py`: `FOIA_SKIP_AI_SERVER` 환경변수 추가 — 테스트 중에는 별도 uvicorn
  스레드/사이드카 exe를 띄우는 로컬 AI 서버를 기동하지 않음(실제 포트 바인딩·프로세스
  생성에 테스트가 의존하지 않게 하기 위함). 기본값은 프로덕션과 동일(계속 기동).
- `tests/test_auth.py`: 로그인 성공/실패, 세션 없는 페이지·API 접근 차단, 계정 잠금
  (5회 실패 → 429), 로그아웃.
- `tests/test_rbac.py`: **FOIA-0019 회귀 테스트** — 배정담당자가 `/requests/{id}/notice`에
  직접 접근해도 차단되는지, 상세 화면에서 최종 통지·판단 트레일이 가려지는지, 총괄관리자·
  배정 담당 업무담당자는 계속 정상 접근되는지. `/requester-history` 정확 일치 검색·역할
  스코프, `/admin/users` 권한 경계도 포함.
- `tests/test_workflow.py`: 배정 → 거절(재배정 후보 지명) → 재배정 → 판단(decide) →
  통지 확정 흐름 전체, 잘못된 본문(`read_json_body`) 400 처리(FOIA-0016 회귀).
- `tests/test_admin.py`: 계정 생성/수정(역할·비밀번호)/삭제, 본인 계정 삭제 금지, 다른
  역할의 `/admin/users` 접근 차단.
- **발견**: `app/routers/admin.py`의 "마지막 시스템관리자는 삭제 불가" 분기가 실제로는
  도달 불가능한 죽은 코드임을 테스트 작성 중 확인 — "본인 삭제 금지" 체크가 먼저 실행되고,
  마지막 관리자는 정의상 자기 자신만 삭제 대상이 될 수 있어 항상 그 체크에서 먼저 막힘.
  위험한 코드는 아니고(의도한 결과를 이미 다른 경로로 보장) 삭제할지 여부는 이번 범위에서
  판단하지 않고 다음 조치로 남김.

### 의존성 버전 고정
- `requirements.txt`: `fastapi`/`uvicorn`/`jinja2`/`python-multipart`/`httpx` 전부 현재
  개발 환경에 설치돼 검증된 정확한 버전으로 `==` 고정(기존엔 `>=` 하한선만 있어 설치
  시점마다 다른 조합이 깔릴 수 있었음).
- `requirements-dev.txt` 신규: `pytest==9.1.1`만 추가 — 배포 서버에는 설치하지 않아 기존
  "최소 의존성" 원칙 유지, 테스트 실행 시에만 별도 설치.
- `README.md`에 "테스트 실행" 절 추가, `DEFAULT_ACCOUNTS` 위치가 `app/main.py`에서
  `app/deps.py`로 이동한 걸 반영 안 하던 stale 참조도 같이 수정.
- `docs/PROJECT_REVIEW.md`: 해당하는 두 항목을 "수정 완료"로 갱신, 우선순위 2 목록의
  4·5번 항목에 취소선 추가.
