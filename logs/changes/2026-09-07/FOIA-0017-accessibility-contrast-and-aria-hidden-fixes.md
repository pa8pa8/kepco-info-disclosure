## 변경 요약
"디자인적" 점검 항목 중 실행 가능한 두 가지(색상 대비, 장식용 이모지 접근성)를 처리.
공식 KRDS 컴포넌트 라이브러리 적용은 Figma 접근 수단이 없어 이번에도 보류.

## 변경 내용
- `app/static/css/style.css`: WCAG 명도대비 계산 결과 `--muted`(회색, 4.26:1)와
  `--warn`(주황, 3.82:1)이 작은 글씨 기준 AA 4.5:1에 못 미쳐 `#5c6884`(4.92:1),
  `#9c6209`(5.04:1)로 조정. 같은 색상군 유지, 파생되는 모든 사용처(상태알약, 버튼,
  링크 등)에 자동 반영됨.
- `app/templates/dispatch.html`, `app/static/js/app.js`: 텍스트와 중복되는 장식용
  이모지 아이콘(빈 상태 아이콘, 대시보드 요약카드 아이콘)에 `aria-hidden="true"` 추가 —
  스크린리더가 "봉투 이모지, 접수된 청구가 없습니다"처럼 중복 안내하지 않도록 함.

## 원인
사용자 지시 "순서대로 진행해줘: 5,1,2,3,4,6" — 직전 6개 관점 점검 보고서의 "디자인적"
항목(웹접근성 미검증)을 우선 처리.

## 검증
- 확인 방법: Python으로 WCAG 2.1 상대휘도 공식을 직접 구현해 주요 텍스트/배경 색상
  조합 11개의 명도대비를 계산 — 조정 전 2건이 4.5 미만(4.26, 3.82)이었고, 조정 후
  전부 4.5 이상 확인. Playwright로 대시보드 스크린샷 재확인(시각적 회귀 없음).
- 결과: 11개 조합 전부 AA 통과. 화면상 색감 차이는 미세함.

## 리스크
- 영향 범위: CSS 변수 2개 변경이 전역에 영향(모든 화면의 muted 텍스트·warning 상태알약
  색이 살짝 진해짐) — 의도된 변경.
- 주의사항: `.summary-card.warning .sc-label` 등 변수가 아닌 하드코딩된 파생 색상 몇 개는
  이번에 재검증하지 않음(2차 라벨 텍스트로 영향이 작음). "🤖 AI 판단하기"처럼 이모지 뒤에
  실제 라벨이 바로 붙는 버튼 텍스트는 손대지 않음 — 이미 스크린리더가 전체 텍스트를
  읽어주므로 접근성 결함이 아니라고 판단.
