## 변경 요약
6개 관점 점검 보고서의 "3. 기능적" 항목 중 가장 심각한 건: 배정담당자가 자신이
관여하지 않은 청구건의 최종 판단 결과·통지문 전문·AI 힌트까지 그대로 열람 가능했던
문제를 차단. 같은 카테고리에서 발견된 "처리 이력" 표의 레이아웃 일관성 문제도 함께
정리.

## 변경 내용

### 배정담당자 판단정보 과다노출 차단
- `app/routers/requests.py`의 `request_detail()`에 `dispatcher_limited_view` 플래그
  추가 — 배정담당자이면서 이미 배정이 끝난 건(`can_assign == False`)일 때 True.
  이때 `log_rows`도 배정/재배정/거절 이력만 남기고 법적 판단 단계(반복청구·정보
  해당·진정질의 등 Y-N 응답) 로그는 제외.
- `app/templates/request_detail.html`: 위 플래그로 다음을 가림 — AI 힌트(진정질의
  가능성/비공개 키워드), "반복 청구 판정" 카드, "판단 경로" 트레일(대신 "배정담당자는
  판단 세부 내용을 열람할 수 없습니다" 안내문 표시), "최종 통지" 본문(대신 처리 상태
  pill만 표시).
- **라우트 레벨 차단**: 템플릿에서 "통지서 보기/인쇄" 링크만 숨기는 것으로는 배정담당자가
  `GET /requests/{id}/notice` URL에 직접 접근하면 통지서 전문을 그대로 볼 수 있는
  허점이 실제 테스트로 확인됨. `request_notice()`의 `require_role`에서 `DISPATCHER`를
  아예 제외(`MANAGER`, `STAFF`만 허용)해 라우트 자체를 차단 — UI를 우회해도 서버가
  거부한다.

### 처리 이력 표 레이아웃
- `request_detail.html`의 "처리 이력" 테이블에 `table-fixed` + `col-time`/`col-target`/
  `col-name` 클래스 적용 — 다른 화면(청구 목록, 청구인 이력)과 표 레이아웃 방식을
  통일.

## 원인
사용자 지시 "5,1,2,3,4,6 순서로 진행해줘" — 디자인(5)·디렉토리/파일명(1)·명칭
통일성(2)에 이어 3(기능적) 진행. 원 점검 보고서에서 "배정담당자는 판단은 불가한
역할인데 관련 없는 청구의 판단 세부 내용까지 열람 가능"이 기능적 카테고리의 가장
심각한 항목으로 지적됨.

## 검증
- 확인 방법: `python -m compileall app` 통과. 격리된 테스트 서버(포트 8085,
  임시 DB)에 배정 완료 상태의 테스트 청구 1건(청구인/통지문 포함)을 직접 시딩한 뒤
  Python `requests`로 역할별 시나리오 검증:
  - 배정담당자가 `/requests/{id}/notice`에 직접 접근 → `require_role`이 403 대신
    303으로 `/dispatch`(자신의 홈)로 리다이렉트, 통지 내용 노출 없음.
  - 배정담당자가 `/requests/{id}` 상세 화면 접근 → 200 정상 렌더링, "통지서 보기"
    링크는 응답 본문에 없음(숨김 확인).
  - 총괄관리자(manager)와 배정 담당 업무담당자(staff1, 소유자)는 동일 URL에서
    변화 없이 200으로 통지서 전문 접근 가능 — 이번 변경이 정상 업무 흐름을
    막지 않음을 확인.
- 결과: 라우트·템플릿 양쪽에서 배정담당자의 판단정보 접근이 일관되게 차단됨.
  회귀 없음.

## 리스크
- 영향 범위: `request_detail.html`(배정담당자로 열람 시에만 렌더링 분기), 통지서
  인쇄 라우트(배정담당자 완전 차단). 관리자/업무담당자 경로는 변경 없음.
- 주의사항: 앞으로 배정담당자가 새로 봐야 할 정보가 생기면 `dispatcher_limited_view`
  분기를 개별적으로 추가/제거해야 한다 — 이 플래그가 "판단 관련 정보 노출 여부"의
  단일 기준이 되도록 유지할 것.
